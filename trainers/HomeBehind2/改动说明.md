## 十三、装备 / 饰品词条不再出现负面（新增）

### 27. 制造 / 掉落装备的词条恒为正面 ✅
- **类 / 方法**：`ReGameController` · `ManageSpeBuffByValue(int, HeroSpeAddData, int)`（`StartMenu` 的同名方法**共用同一段 IL**，方法体 RVA `0xF3328`）
- **参数**：方法最后一个 `for` 循环的词条赋值
- **变化**：
  - `heroSpeAddData[index5] + (float)list[m] * speValue`
    → `heroSpeAddData[index5] + Mathf.Abs((float)list[m]) * speValue`
  - 顺带等价简化：`Random.Range(0, Enum.GetValues(typeof(HeroSpeAddDataType)).Length)` → `Random.Range(0, 26)`（枚举共 26 项，取值完全相同，仅为腾出 5 字节让补丁等长）
- **原理**：`ManageSpeBuffByValue` 把 `targetValue` 随机拆成 `num2` 份（`list[] = targetValue + 10*num2` 的随机分割，每份再减 10 并重新分配）；拆分与再分配过程会让某些份落到 **负值**，这份负值乘上 `speValue` 后写进 `speAddData`，就是游戏里红色的**负面词条**。
  取绝对值后每条词条的贡献恒为正 → **不再出现负面词条**；词条条数不变，数值大小仍按原分布（负值翻正），装备整体略强于原版。
- **影响面**（该方法是共用方法，做不到只作用于制作）：
  - ✅ 车间「防具制作」「饰品制作」产物
  - ✅ 战利品 / 商店 / 任务奖励里的武器、防具、饰品
  - ✅ 初始天赋（`StartMenu`）、NPC 天赋（`NpcArmy`）、报纸随机天赋、`RePlayer` 里的随机天赋
  - 即：**全游戏不再刷出负面词条**，NPC 也会因此略强
- **若只想改「制作」**：需换思路——在三个生成器（`ArmorSpeGenerator` / `DecorationGenerator` / `WeaponGenerator`）调用 `ManageSpeBuffByValue` 之后，各加一段「负值翻正」的小循环。
- **补丁方式**：`work/patch_affix.py`（等长字节替换，**未改动元数据、文件大小不变**；仅 89 字节区域内 84 字节不同）
- 注：`speValue` 自带正负号（如 `supMulti` 减补给消耗为负号），`Mathf.Abs` 作用在「份值」上、不作用在 `speValue` 上，因此带负号的属性依然显示为绿色正面词条。

## 复核方式

```bash
cd trainers/HomeBehind2

# 重新跑「原版 ⇄ 改版」对照（会重新反编译两份）
python work/diff_asm.py --original original/Assembly-CSharp.dll

# 字段级语义对比（绕开 dnSpy 重编译噪音）
python work/fieldcmp.py diff_out/src_original/GlobalData.cs diff_out/src_modified/GlobalData.cs
```

> 提示：`diff_asm.py` 若发现 `diff_out/src_*` 已存在会**跳过反编译**（用旧产物）。
> 重新对照前先 `rm -rf diff_out`，或加 `--out 新目录`。

### 可用的反编译 / 反汇编命令（dnSpy 6.1.8）

```bash
# 反编译整个 Assembly-CSharp.dll（bash 下直接跑 dnSpy.Console.exe 会因「无控制台」报
# “句柄无效”而静默失败，必须用 conhost --headless 起一个 headless 控制台 + dotnet 运行）
cd /d/02-Tools/21-dnSpy
DOTNET_ROLL_FORWARD=Major conhost.exe --headless "C:\Program Files\dotnet\dotnet.exe" \
  exec "D:\02-Tools\21-dnSpy\bin\dnSpy.Console.dll" --no-color \
  -o "<输出目录>" "<Assembly-CSharp.dll 路径>"

# 查看某方法的 IL（需 pip install dnfile dncil）
python work/show_il.py <dll路径> 0xF3328      # 例：ManageSpeBuffByValue
```

`work/` 下三个脚本：

| 文件 | 用途 |
|---|---|
| `patch_affix.py` | 第 27 条的字节补丁（等长替换，自带原文校验） |
| `show_il.py` | 按 RVA 反汇编方法体 IL，用来定位指令级改动点 |
| `list_methods.py` | 按类名列出方法的 MethodDef token 与 RVA |
| `src_mod/` | 当前 `Assembly-CSharp.dll` 的反编译源码，可直接全文检索 |

> 定位技巧：先 `list_methods.py` 拿 RVA → `show_il.py` 看 IL → 用`dnfile`读字节确认唯一性 → 等长替换 → 重新反编译 + 全量 `diff` 验证只有预期处变化。
