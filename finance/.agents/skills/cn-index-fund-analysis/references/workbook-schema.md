# 工作簿Schema与同步规则

结构的机器可读定义位于 `workbook-schema.json`。模板、校验脚本和计算脚本必须共同使用该文件；若字段发生变化，先更新JSON，再更新模板和测试。

## 基金信息

表头在第5行，数据从第6行开始。核心字段：基金代码、基金名称、主题、跟踪指数、关联场内ETF代码/名称、交易所、行情SecID、成立日期、销售服务费、赎回费、天天基金页面、信息同步日期。

- 基金代码、ETF代码展示为六位。
- `行情SecID` 用于东方财富行情接口：深市通常为 `0.代码`，沪市通常为 `1.代码`。
- `行情SecID` 必须以文本存储，并严格符合 `^[01]\.[0-9]{6}$`；只把单元格格式改为“文本”而不重新写入值，不算完成转换。
- `行情SecID` 超链接为可选项；如添加，应指向对应场内ETF的东方财富行情页，不要重复链接到场外基金详情页。
- 没有关联ETF的普通指数基金允许ETF字段为空；此时只能分析基金净值K线，不能下“放量”结论。
- 关联ETF无法唯一识别时留空并报警。

## 交易流水

表头在第5行，数据从第6行开始。代码按表头名称定位，不依赖固定列号。

- 买入、定投、转换转入：增加份额，成本为申请/成交金额加手续费。
- 卖出、转换转出：按移动加权平均成本减少份额；优先使用实际到账，缺失时使用成交金额，再缺失时用份额×确认净值−手续费估算并报警。
- 待确认交易不改变已确认持仓。
- 现金分红计入已实现现金流，不减少份额。
- 转换转入没有对应转换转出时报警。
- 回本所需涨幅=`剩余亏损/当前市值`。

## 分析分支

1. 从基金信息和交易流水收集全部基金代码。
2. 基金信息缺失：先查天天基金并同步。
3. 无交易记录或确认持仓为零：仅输出技术面。
4. 有确认持仓：输出持仓成本、盈亏、交易问题、重合度和技术面。
5. 无关联ETF：只分析净值均线，不分析量能。

## 验收

- `validate_workbook.py` 返回OK。
- 基金信息字段与JSON完全一致。
- 交易流水公式覆盖到预留行。
- 六位代码未丢失前导零。
- 行情SecID为文本，市场前缀、六位ETF代码及可选行情超链接均通过校验。
- 关键公式无 `#NAME?/#REF!/#VALUE!`。
- 模板和脚本使用同一Schema版本。
