## 公式怎么读这些多行图

本册所有带 Σ 的公式都用上下排开的形式。以最基础的那个为例：

```
     n
     Σ   xᵢ
    i=1
```

三块，位置就是含义：

```
    ┌─ 上限：加到哪儿停（终点）
    │
    n
    Σ   xᵢ   ← 循环体：每次加什么
   i=1
    │
    └─ 下限：从哪开始（同时声明变量 i）
```

**Σ 本身没有"值"**，它只是一个"把下面这些东西加起来"的指令。真正被计算的是 `xᵢ`。

三块对应的 Java：

```java
double s = 0;                        // ← Σ：准备一个累加器
for (int i = 1; i <= n; i++) {       // ← i=1（下） 和 n（上）
    s += x[i];                       // ← xᵢ：循环体
}
```

**读的顺序固定是"先下后上"**：sum from `i=1` to `n`。

多层的 Σ 就一层一层套：

```
     n    n
     Σ    Σ   Xᵢⱼ        ← 读 "sum over i, sum over j"
    i=1  j=1
```

对应两个嵌套的 `for`。

## 五个必踩的坑

1. **`log` 是 ln。**
   论文里看到 `log` 一律当自然对数。`ln(2)=0.693`，不是 `0.301`。
   Java 里就是 `Math.log`，不是 `Math.log10`。

2. **`aᵀb` 和 `abᵀ` 完全不是一回事。**
   前者是一个**数**（点积，读 "a transpose b"），后者是一个**矩阵**（外积，读 "a b transpose"）。
   转置符号贴在谁身上，结果就完全不同。第 9 题会让你把两个都写一遍。

3. **`⊙` 不是矩阵乘。**
   `⊙` 逐元素，读作 "hadamard"。`AB` 才是矩阵乘，读作 "A times B"。

4. **`argmax` 返回下标，`max` 返回值。**
   混淆会写出能跑但全错的代码。这是实现 attention、解码、评测时最常见的 bug。

5. **论文里所有东西都是批量的。**
   你看到的 `X ∈ ℝᵈ` 实际是 `X ∈ ℝ^(B×T×d)`，多了 batch 和序列两维。
   **第一次读公式先假装 B=T=1**，把逻辑理清，再补维度。

# 第 1 组 · 一次循环（热身）

## 1. 求和

**原式**：

```
     n
     Σ   xᵢ
    i=1
```

**读作**：sum from i equals one to n, of x sub i

**人话**：把 x 的第 1 项到第 n 项全加一遍。

**代入具体数字**（`x = [3,1,4,1,5]`，n = 5）：

```
     5
     Σ   xᵢ  =  x₁ + x₂ + x₃ + x₄ + x₅
    i=1
            =  3 + 1 + 4 + 1 + 5
            =  14
```

**四部分对齐**：

| 数学 | 位置 | Java |
|---|---|---|
| `Σ` | 累加号 | `double s = 0;` 然后 `s +=` |
| `i=1` | **下**限（起点） | `int i = 1` |
| `n` | **上**限（终点） | `i <= n` |
| `xᵢ` | 循环体 | `x[i]` |

**写**：`double sum(double[] x)`

**对答案**：`[3,1,4,1,5]` → `14.0`

---

## 2. 均值与方差与标准差

**原式**（三个公式，逐个看）：

均值：

```
              n
     μ  =  (1/n)  Σ   xᵢ
             i=1
```

方差：

```
                n
     σ²  =  (1/n)  Σ  (xᵢ - μ)²
                i=1
```

标准差：

```
     σ  =  √( σ² )
```

**读作**：

> "mu equals one over n, times sum from i equals one to n, of x sub i"
> "sigma squared equals one over n, times sum from i equals one to n, of, x sub i minus mu, squared"
> "sigma equals square root of sigma squared"

**符号**：

- `μ` 读 **"mu"** /mjuː/（"缪"）= 均值
- `σ` 读 **"sigma"** /ˈsɪɡmə/（"西格马"）= 标准差
- `σ²` 读 **"sigma squared"** = 方差（标准差的平方）

**人话**：先算平均 μ，再看每个数偏离平均多少、平方、求平均得到方差 σ²，开根得标准差 σ。σ 是"散布程度"。

**为什么先平方再开根**：偏离有正有负，直接平均会互相抵消（`-3 + 3 = 0`）。平方后全变正，加起来才有意义；最后开根把单位还原回去。

**四部分对齐**（以 σ² 为例）：

| 数学 | Java |
|---|---|
| `Σ (xᵢ - μ)²` | 循环累加 `(x[i]-mu)*(x[i]-mu)` |
| `(1/n)` | 除以 `x.length` |
| `σ²` | 结果 |
| `√σ²` | `Math.sqrt(var)` |

**写**：`double mean(double[] x)`、`double variance(double[] x)`、`double std(double[] x)`

**对答案**：
- `[2,4,4,4,5,5,7,9]` → `mean=5.0`，`var=4.0`，`std=2.0`
- `[3,1,4,1,5]` → `mean=2.8`，`var=2.56`，`std=1.6`

> 这是 `1/n`（总体标准差）的版本，不是 `1/(n-1)`（样本）。先按 `1/n` 写。

## 3. 最大值下标

**原式**：

```
     argmax  xᵢ
           i
```

**读作**：arg max over i, of x sub i

**人话**：哪个位置上的数最大？返回**位置**，不是数值。

**`arg` 是什么**：argument 的缩写，意思是"让函数取到极值的那个**自变量**"。

```
     max  xᵢ   →  读 "max over i"      →  最大那个数本身
       i

     argmax  xᵢ →  读 "arg max over i" →  它在第几个位置
           i
```

举例：`x = [5, 9, 2]`
- `maxᵢ xᵢ = 9`
- `argmaxᵢ xᵢ = 1`（如果从 0 数）或 `2`（如果从 1 数）

**写**：`int argmax(double[] x)`

**对答案**：`[0.1, 2.3, 0.7, -1, 5.2]` → `4`（不是 `5.2`）

## 4. exp 与 log 的肌肉记忆

**原式**：

```
     exp(x) = eˣ
     log(x) = ln x
```

**读作**：`exp(x)` 读 "exp of x" 或 "e to the x"；`ln(x)` 读 "natural log of x"；`e` 读字母 **e**。

**人话**：`exp` 和 `ln` 互为逆运算。`log` 在 ML 论文里**就是 ln**。

**跑出来并背下这几个值**：

```java
System.out.println(Math.exp(0));    // 1.0
System.out.println(Math.exp(1));    // 2.718281828459045
System.out.println(Math.exp(-1));   // 0.36787944117144233
System.out.println(Math.log(1));    // 0.0
System.out.println(Math.log(2));    // 0.6931471805599453
System.out.println(Math.log(10));   // 2.302585092994046
System.out.println(Math.log(0.5));  // -0.6931471805599453
```

**记住这 4 个**：`ln2 ≈ 0.693`、`ln10 ≈ 2.303`、`e ≈ 2.718`、`ln1 = 0`

以后看训练日志全靠它们。

# 第 2 组 · 两层循环（矩阵）

## 5. 点积

**原式**：

```
                   n
     ⟨a, b⟩  =     Σ   aᵢ bᵢ
                  i=1
```

**读作**：angle bracket a comma b, equals sum from i equals one to n, of a sub i times b sub i

`⟨⟩` 读 **"angle bracket"**（尖括号），也读 "inner product"（内积）。

**人话**：对应位置相乘再全加。注意两边下标**都是 i**——同一个索引，两个数组同步走。

**关键：下标是不是同一个字母，决定了两件完全不同的事**

```
                n
     Σ  aᵢ bᵢ  =  a₁b₁ + a₂b₂ + ... + aₙbₙ      ← 同一索引 i，n 项
   i=1

      n    n
      Σ    Σ  aᵢ bⱼ  =  (a₁+a₂+...+aₙ)(b₁+b₂+...+bₙ)   ← 两个独立索引，n² 项
     i=1  j=1
```

用具体数字（`a = [1,2,3]`，`b = [4,5,6]`）：

**情况一**（同一索引 → 点积，3 项）：

```
                   3
     ⟨a,b⟩   =     Σ   aᵢ bᵢ   =   1·4 + 2·5 + 3·6   =   32
                  i=1
```

**情况二**（两个独立索引 → 全组合，9 项）：

```
                   3    3
                   Σ    Σ   aᵢ bⱼ   =   (1+2+3)·(4+5+6)   =   6 · 15   =   90
                  i=1  j=1
```

| 式子 | 结果 | 项数 |
|---|---|---|
| 情况一（单层 Σ） | `32` | 3 |
| 情况二（双层 Σ） | `90` | 9 |

两个式子看起来几乎一样，结果差近 3 倍。**区分它们的唯一线索是下标是不是同一个字母。**

**写**：`double dot(double[] a, double[] b)`

**对答案**：`[1,2,3]·[4,5,6]` → `32.0`

## 6. 欧几里得范数（L2 范数）

**注意符号**：欧几里得范数写作 **`‖x‖₂`**，右下角的 `2` 不是装饰——它指定"哪一种范数"。

**原式**：

```
                    n
     ‖x‖₂  =  √(     Σ   xᵢ²  )
                   i=1
```

**读作**：L two norm of x, equals square root of, sum from i equals one to n, of x sub i squared

简化读法：**"L two norm of x"**，或 "the Euclidean norm of x"。

**人话**：勾股定理的 n 维版。每个元素平方、全加、开根。

**为什么必须有下标 2**：范数不止一种。同一个向量，不同范数给出不同数值：

```
向量 x = [3, 4]

L1 范数：  ‖x‖₁  = |3| + |4|              = 7      ← 绝对值相加（曼哈顿距离）
L2 范数：  ‖x‖₂  = √(3² + 4²)             = 5      ← 平方和开根（欧氏距离）
L∞ 范数：  ‖x‖∞  = max(|3|, |4|)          = 4      ← 取最大绝对值
```

三个都是"范数"，数值完全不同。**所以 `‖x‖₂` 里的 2 不能省。**

（ML 里如果只写 `‖x‖` 不加下标，通常默认指 L2，但看到没下标的要先确认上下文。）

**在 ML 里的用途**：L2 正则化就是惩罚 `‖W‖₂²`，让权重变小；embedding 的相似度计算也基于它。

**写**：`double norm2(double[] x)`

**对答案**：
- `[3,4]` → `5.0`
- `[1,1,1,1]` → `2.0`
- `[0,0,0]` → `0.0`

**进阶（可选，5 分钟）**：顺手把 `l1Norm` 和 `linfNorm` 也写了，验证上面那张表。写完你就永远不会把三种范数搞混。

## 7. 余弦相似度（RAG 检索的核心）

**原式**：

```
                    ⟨a,b⟩                    n
     cos(a,b)  =  ───────────  =  ⟨a,b⟩ / (   Σ  aᵢ² )^½ · ( ... )
                   ‖a‖₂ ‖b‖₂
```

写成能直接对照代码的形式：

```
     cos(a,b)  =  ⟨a,b⟩  /  ( ‖a‖₂ · ‖b‖₂ )
```

**读作**：cos of a comma b, equals angle bracket a b, over, L two norm of a times L two norm of b

**人话**：点积除以两个长度，把结果压到 -1~1 区间。**这就是 embedding 检索在算的东西。**

**几何意义**：两个向量的夹角余弦。分母的作用是把长度除掉，于是只比较"方向"。

| 值 | 含义 |
|---|---|
| `1` | 完全同向（最相似） |
| `0` | 正交（无关） |
| `-1` | 完全反向 |

**为什么检索用它**：两个长度不同的向量，点积会被长度带偏（长向量点积天然大）。除以长度后只剩方向信息，才能公平比较。

**写**：`double cosine(double[] a, double[] b)`

**对答案**：`[1,2,3]` 与 `[4,5,6]` → `≈0.9746`

**必须验证的两条**：
- 自己跟自己的余弦相似度 = `1.0`（浮点误差内）
- 结果永远落在 `[-1, 1]` 内（超出去说明写错了）

## 8. 矩阵乘

**原式**：

```
                    K
     Cᵢⱼ  =        Σ   Aᵢₖ Bₖⱼ          即   C = AB
                   k=1
```

**读作**：C sub i j, equals sum from k equals one to K, of, A sub i k times B sub k j

**人话**：C 的第 i 行第 j 列 = **A 的第 i 行** 和 **B 的第 j 列** 做点积。三层循环。

**最重要的规则：被 Σ 绑住的索引会消失**

```
     Cᵢⱼ  =  Σ  Aᵢₖ Bₖⱼ
              k
      ↑↑     ↑  ↑
      ││     │  └─ k 也被绑住 → 消失
      ││     └──── k 被 Σ 绑住 → 消失
      │└────────── 自由索引 j → 留下
      └─────────── 自由索引 i → 留下

     结果：C 的形状是 (i 的范围) × (j 的范围)
```

**左边是 `ᵢⱼ`（两个自由索引），右边求和的是 `ₖ`。只有 k 被吃掉，i 和 j 留下来决定输出形状。**

这条规则适用于读任何论文公式：**看哪些下标被 Σ 绑住，剩下几个，就知道输出是什么形状。**

**对答案**：

```
A = [[1,2,3],           (2×3)
     [4,5,6]]

B = [[7,8],             (3×2)
     [9,10],
     [11,12]]

AB = [[58,  64],        (2×2)
      [139, 154]]
```

**验算一个位置**：`C₀₀ = 58` 怎么来的？

```
A 的第 0 行 = [1,2,3]
B 的第 0 列 = [7,9,11]
               
     Σ  = 1·7 + 2·9 + 3·11 = 7 + 18 + 33 = 58   ✓
```

**必须验证 shape**：`(2,3) @ (3,2) → (2,2)`。中间那个 3 被吃掉：

```
     (m,k) @ (k,n)  →  (m,n)
             ↑
        必须相等，否则该报错
```

写完在 `matmul` 开头加一句 shape 检查，不匹配直接 `throw`。以后调试模型时 90% 的报错靠它定位。

**写**：`double[][] matmul(double[][] A, double[][] B)`

## 9. 转置与两种乘法（坑 #2 的解药）

**原式**：

转置：

```
     (Aᵀ)ᵢⱼ  =  Aⱼᵢ
```

外积：

```
     (abᵀ)ᵢⱼ  =  aᵢ bⱼ
```

**读作**：`Aᵀ` 读 **"A transpose"**；`(Aᵀ)ᵢⱼ` 读 "A transpose sub i j"；`abᵀ` 读 **"a b transpose"**。

**人话**：
- **转置**：行列互换，`A[i][j]` 变成 `A[j][i]`，形状 `(m,n)` → `(n,m)`
- **外积** `abᵀ`：两个向量做出一整个矩阵

**先把向量当列向量**（数学惯例）。设 `a = [1,2,3]ᵀ`、`b = [4,5,6]ᵀ`，两者都是 **3×1 列向量**：

**情况一：`aᵀb`（读 "a transpose b"）= 点积 = 一个数**

```
     aᵀ  ·  b
    (1×3)(3×1)   →   1×1   一个数

     = 1·4 + 2·5 + 3·6 = 32
```

**情况二：`abᵀ`（读 "a b transpose"）= 外积 = 一个矩阵**

```
     a  ·  bᵀ
    (3×1)(1×3)   →   3×3   一个矩阵

     = [[ 4,  5,  6],
        [ 8, 10, 12],
        [12, 15, 18]]
```

**只差转置符号贴在谁身上，结果一个数、一个矩阵。**

验算一个元素：`(abᵀ)ᵢⱼ = aᵢbⱼ`。取 i=2（第 3 个）、j=0（第 1 个）：`3 × 4 = 12` ✓，正是右下角那行的第一个数。

**写**：
- `double[][] transpose(double[][] A)`
- `double[][] outer(double[] a, double[] b)`

**对答案**：见上。两个都写一遍、都打印出来，你会永远记住 `aᵀb` ≠ `abᵀ`。

> 顺手验证形状：`transpose` 把 `(2,3)` 变成 `(3,2)`；`outer` 把两个长度 3 的向量变成 `(3,3)`。

# 第 3 组 · 把数变成概率

## 10. softmax

**原式**：

```
                                    exp(zᵢ)
     softmax(z)ᵢ   =   ────────────────────────────
                                  n
                                  Σ   exp(zⱼ)
                                 j=1
```

**读作**：softmax of z index i, equals exp of z sub i, over, sum from j equals one to n, of exp of z sub j

**人话**：每个数取 exp（变成正数），再除以总和（归一化成概率）。结果全为正、加起来等于 1。

**这就是 LLM 的最后一步**：把 logits 变成词表上的概率分布。

**对照第 1 题**：分母和求和那条一模一样，只是加的是 `exp(zⱼ)` 而不是 `zⱼ`。`exp` 的作用是保证全为正数——否则负数除以总和会得到负概率。

**注意下标是 `j` 不是 `i`**：分子固定看第 i 个，分母要把**所有** j 都加一遍。这是"第 i 个占全部的多少"。

**写**：`double[] softmax(double[] z)`

**对答案**：`[2, 1, 0.5]` → `[0.6285, 0.2312, 0.1402]`

**验证**：`sum(输出) == 1.0`（误差内）

## 10b. softmaxStable（工程必做）

**原式**：

```
                                    exp(zᵢ - max(z))
     softmax(z)ᵢ   =   ──────────────────────────────────────
                                  n
                                  Σ   exp(zⱼ - max(z))
                                 j=1
```

**读作**：……equals exp of, z sub i minus max of z, over, sum from j equals one to n, of exp of, z sub j minus max of z

**人话**：先减掉最大值再算。**结果和原来完全一样**，但不会溢出。

**为什么可以减**：分子分母同乘 `e⁻ᵐᵃˣ`，比值不变。也就是这条恒等式：

```
     exp(a-b) / exp(c-b)  =  exp(a) / exp(c)
```

**为什么必须这么做**：浮点数里 `exp(1000)` 直接变 `Infinity`，然后 `Infinity / Infinity` = `NaN`。模型一旦输出大 logit 就全崩。所有推理引擎都这么写。

**写**：`double[] softmaxStable(double[] z)`

**对答案**：

| 输入 | 输出 |
|---|---|
| `[1000, 1001, 1002]` | `[0.0900, 0.2447, 0.6652]` |
| `[0, 1, 2]` | `[0.0900, 0.2447, 0.6652]` ← 完全一样 |

> 两个数组整体差 1000，输出一模一样——这就是"平移不变性"，也是减 max 合法的根据。

**进阶：温度**。`softmax(z / T)`，`T` 读 **"tau"** /taʊ/（"陶"）：

| T | 现象 |
|---|---|
| `T=10` | 分布变平（接近均匀，1/n） |
| `T=1` | 原始分布 |
| `T=0.1` | 分布变尖（接近 one-hot） |
| `T→0` | 退化成 argmax |

打印出来对比。**这就是 API 里 `temperature` 参数的真身**，你以后调它会有完全不同的感觉。

## 11. 交叉熵

**原式**：

```
                      n
     L   =   -        Σ   yᵢ log(pᵢ)
                     i=1
```

**读作**：L equals minus, sum from i equals one to n, of, y sub i log p sub i

`L` 读 **"L"** 或 **"loss"**。`log` 在这里是**自然对数**（ln），不是 log10。

**人话**：因为 y 是 one-hot（只有一个位置是 1，其余全 0），所以整个求和里只有一项活着，等价于：

```
     L  =  -log( p_correct )
```

其余项都被 `yᵢ = 0` 乘没了。**这是"看起来复杂、实际只有一项"的典型例子**——读公式时先看哪些项实际是 0。

**为什么用 log**：log 在小概率处极其敏感。

| `p_correct` | `L = -log(p)` | 含义 |
|---|---|---|
| `0.9` | `0.105` | 很确信且正确 |
| `0.5` | `0.693` | = ln2，**二分类瞎猜** |
| `0.1` | `2.303` | = ln10，**十选一瞎猜** |
| `0.01` | `4.605` | 确信地错，重罚 |
| `1.0`（极限） | `0.0` | 完全正确 |
| `→ 0`（极限） | `→ ∞` | 完全错，罚到无穷 |

概率从 `0.5` 掉到 `0.01`，损失涨了六倍多。**模型越确信地错，惩罚越重**——这正是分类任务想要的。

**写**：`double crossEntropy(double[] p, int correctIdx)`

**对答案**：

| 用例 | 期望值 |
|---|---|
| `p_correct = 0.9` | `0.1054` |
| `p_correct = 0.5` | `0.6931` |
| `p_correct = 0.1` | `2.3026` |
| 第 10 题的输出，correct = 0 | `0.4644` |
| `p_correct = 1.0` | `0.0` |

**这三个数字要背下来。** 以后看训练日志：

- loss 卡在 `0.693` → 二分类模型完全没学
- loss 卡在 `2.303` → 十选一在瞎猜
- loss 是 `0.5` → 有进步但不够

**"数学直觉好"就是这么来的，不是靠推公式，是靠脑子里有一堆基准数字。**

## 12. 期望

**原式**：

```
                                 
     E [f(x)]   =        Σ     p(x) f(x)
      x~p                x∈D
```

**读作**：expectation over x from p, of f of x, equals sum over x in D, of p of x times f of x

**符号**：
- `E` 读 **"expectation"**（期望）
- `x ~ p` 读 **"x distributed as p"**（x 服从分布 p）
- `x ∈ D` 读 **"x in D"**（x 遍历集合 D）

**人话**：按概率加权平均。概率大的项权重大。

**对照第 1 题**：结构完全一样，只是每一项多乘了个权重 `p(x)`。

**自检**：`p` 全相等时，期望应该退化成普通平均。拿 `p = [0.25, 0.25, 0.25, 0.25]` 试，`expect` 的结果必须等于 `mean(f)`。**这个自检能抓出绝大多数写错。**

**写**：`double expect(double[] p, double[] f)`

**对答案**：`p=[0.1,0.2,0.7]`、`f=[0,10,100]` → `72.0`

## 13. KL 散度

**原式**：

```
                                          pᵢ
     D_KL(p‖q)   =        Σ        pᵢ log( ──── )
                         i∈D              qᵢ
```

**读作**：D K L between p and q, equals sum over i in D, of, p sub i log, p sub i over q sub i

**符号**：
- `D_KL` 读 **"K L divergence"** 或 "kay-ell"
- `‖` 在这里读 **"between"**（注意：在范数里读 "norm"，同一符号两种读法）

**人话**：用 q 去近似 p，要多付多少代价。等于 0 表示完全一样。

**它不对称**：`KL(p‖q) ≠ KL(q‖p)`。因为它不是"距离"，是"代价"——用 q 近似 p 和用 p 近似 q，代价不同。

**写**：`double kl(double[] p, double[] q)`

**对答案**：

| 计算 | 结果 |
|---|---|
| `p=[0.5,0.5]`、`q=[0.9,0.1]` → `KL(p‖q)` | `≈ 0.5108` |
| 反过来 → `KL(q‖p)` | `≈ 0.3681` |

**两个数不一样，这就是它不对称的证明。** 用代码看到这行差异，比读定义强十倍。

**边界自检**：`p` 和 `q` 完全相同时，结果必须是 `0`。

# 第 4 组 · 梯度（核心）

## 14. 数值导数（你未来几个月的调试神器）

**原式**：

```
                     f(x + h) - f(x - h)
     f'(x)   ≈     ───────────────────────
                              2h
```

**读作**：f prime of x, approximately equals, f of x plus h minus f of x minus h, over two h

`f'(x)` 读 **"f prime of x"**（撇号读 prime）。`h` 是步长，读 "h"。

**人话**：左右各走一小步 h，看 f 差多少，除以 2h（总跨度）。

**为什么用中心差分**：向前差分 `(f(x+h)-f(x))/h` 的误差是 `O(h)`，中心差分是 `O(h²)`——精度高一个量级，几乎不花额外成本。

**为什么 h 不能太大也不能太小**：

| h | 问题 |
|---|---|
| `1e-2` | 太大，近似不准（截断误差） |
| `1e-5` | **甜点** |
| `1e-15` | 太小，浮点数一减就归零（抵消误差） |

**写**：`double numericDeriv(DoubleUnaryOperator f, double x)`，内部 `h = 1e-5`

**对答案**：

| 函数 | 点 | 数值导数 | 解析值 |
|---|---|---|---|
| `x²` | `x=3` | `6.0` | `2x = 6` |
| `x³` | `x=2` | `12.0` | `3x² = 12` |
| `ln(x)` | `x=2` | `0.5` | `1/x = 0.5` |
| `sin(x)` | `x=0` | `1.0` | `cos(0) = 1` |

> **这一个方法是你未来几个月的最高杠杆工具。**
> 以后任何梯度你觉得不对，都拿它验。写 autograd 引擎时，每个算子都要过它一遍，误差 `< 1e-6` 才算对。
> 这个习惯能省掉你几周的玄学调试。

## 15. 偏导与梯度

**原式**：

```
     f(x, y)  =  x²y

                        ∂f
                        ──   =  2xy          ← 把 y 当常量
                        ∂x

                        ∂f
                        ──   =  x²           ← 把 x 当常量
                        ∂y

     ∇f  =  [ ∂f/∂x ,  ∂f/∂y ]
```

**读作**：
- `∂` 读 **"partial"**（偏），**不是 "d"**
- `∂f/∂x` 读 "partial f partial x"
- `∇f` 读 **"nabla f"** /ˈnæblə/ 或 "grad f"（梯度）

**人话**：求 `∂f/∂x` 时，把 y 当成 `final` 常量，只剩下 x 一个自变量求导。
`∇f` 就是把每个偏导打包成一个向量。

**手推过程**：

对 `f = x²y` 求 `∂f/∂x`：y 是常量，`x²` 求导得 `2x`，所以结果是 `2xy`。

| 量 | 推导 | 在 (x=2, y=3) 的值 |
|---|---|---|
| `∂f/∂x` | `y` 常量，`x²` → `2x`，乘上 `y` | `2·2·3 = 12` |
| `∂f/∂y` | `x²` 常量，`y` → `1` | `2² = 4` |

**写**：先手推，再写 `double[] numericGrad(DoubleBinaryOperator f, double x, double y)` 验算

**对答案**：`(x=2, y=3)` → `∇f = [12.0, 4.0]`

> 手推的 `2xy = 12`，`x² = 4`。数值算出来对得上，说明你理解对了。
> **"手推 → 数值验算"这个闭环，就是工程师版的数学能力。**

## 16. 梯度下降

**原式**：

```
     θ  ←  θ - η ∇L(θ)
```

**读作**：theta gets theta minus eta nabla L of theta

**符号**：
- `θ` 读 **"theta"** /ˈθiːtə/（"西塔"，咬舌音）= 参数
- `η` 读 **"eta"** /ˈiːtə/（"伊塔"）⚠️ 长得像 n，**不是 n** = 学习率
- `←` 读 **"gets"**（赋值），不是"箭头"
- `∇L` 读 "nabla L" 或 "gradient of L"

**人话**：重复很多次：算梯度，朝反方向挪 `η` 那么多。**训练模型就是这个循环，别无其他。**

**为什么是减不是加**：梯度 `∇L` 指向"loss **上升最快**"的方向。要降低 loss，必须往反方向走。

**写**：

```java
// f(w) = (w-3)²,  ∇f = 2(w-3),  η = 0.1,  w 从 0 开始，迭代 20 次
```

每次打印 `w` 和 `f(w)`。

**对答案**：

```
     w: 0.0 → 0.6 → 1.08 → 1.464 → 1.7712 → ...

     20 步后： w ≈ 2.9654,  f(w) ≈ 0.0012
```

验算第一步：`w₁ = 0 - 0.1 × 2 × (0 - 3) = 0 - 0.1 × (-6) = 0.6` ✓

**然后一定要做这三组实验**：

| η（读 "eta"） | 现象 |
|---|---|
| `0.1` | 正常收敛到 3 |
| `1.1` | **发散**，w 越来越大，`f(w)` 变 `Infinity` |
| `0.001` | 爬得很慢，20 步还差得远 |

**亲眼看到发散，比读十遍"学习率太大会不收敛"有用一万倍。**
这就是你以后调超参时的直觉来源。

## 17. LayerNorm

**原式**：

```
                    x - μ
     y   =     ───────────────────  · γ + β
                √( σ² + ε )
```

**读作**：y equals, x minus mu, over square root of sigma squared plus epsilon, times gamma, plus beta

**符号**：
- `μ` 读 **"mu"** /mjuː/（"缪"）= 均值
- `σ²` 读 **"sigma squared"** = 方差
- `ε` 读 **"epsilon"** /ˈepsɪlɒn/ ⚠️ 重音在第一音节 **EP-si-lon**
- `γ` 读 **"gamma"** /ˈɡæmə/（"伽马"）= 缩放
- `β` 读 **"beta"** /ˈbiːtə/（"贝塔"）= 平移

**人话**：把一组数减均值、除标准差，变成"均值 0、标准差 1"，再用 γ、β 缩放平移回去。

**为什么需要 ε**：如果一组数全都相同，`σ = 0`，除零直接 `NaN`。加个很小的数（`1e-5`）避免。

**为什么还要 γ 和 β**：归一化成"均值 0、标准差 1"太强了，会削掉模型本来需要的表达能力。`γ`、`β` 让模型自己学"该缩放多少、该平移多少"——如果最优解就是"不要归一化"，`γ` 会学到接近 `σ`、`β` 学到接近 `μ`。

**这就是第 2 题的直接应用**：先算 `μ` 和 `σ`（第 2 题），再做 `(x-μ)/σ`。

**写**：`double[] layerNorm(double[] x, double gamma, double beta)`，`ε = 1e-5`

**对答案**：`x=[2,4,4,4,5,5,7,9]`、`γ=1`、`β=0`

```
     [-1.5, -0.5, -0.5, -0.5, 0.0, 0.0, 1.0, 2.0]
```

验算第一个：`(2 - 5) / 2 = -1.5` ✓（μ=5，σ=2，都是第 2 题算过的）

**验证**：
- 输出的 `mean ≈ 0`
- 输出的 `std ≈ 1`

> 你会发现它根本不难，只是名字吓人。
> 这也印证了整本练习册的论点：论文的难度来自**记号密度**，不是概念深度。

# 第 5 组 · Attention（结课作业）

## 18. Attention

**原式**：

```
                                      Q Kᵀ
     Attention(Q, K, V)  =  softmax( ─────── ) · V
                                      √dₖ
```

**读作**：Attention of Q K V, equals softmax of, Q K transpose over square root of d sub k, times V

逐段拆：

| 片段 | 读作 | 含义 |
|---|---|---|
| `Attention(Q, K, V)` | attention of Q-K-V | 三个输入矩阵 |
| `QKᵀ` | **Q K transpose** | Q 乘 K 的转置，得到"相似度分数" |
| `√dₖ` | **square root of d sub k** | dₖ 是每个头的维度，一个**数** |
| `QKᵀ / √dₖ` | Q K transpose **over** square root of d sub k | 缩放，防止数值过大 |
| `softmax(...)` | softmax of ... | **按行**归一化成权重 |
| `· V` | **times V** | 用权重加权 V |

**人话**：三个矩阵 Q、K、V。先用 Q 和 K 算出"谁该看谁"的分数，归一化成注意力权重，再用权重去加权 V。

**Q、K、V 是什么**：同一个输入 `X` 乘三个不同的权重矩阵得到的三个"视角"。
- Q = Query（我在找什么）
- K = Key（我能提供什么）
- V = Value（我实际携带的内容）

**拆成五步，每步都是你已经写过的**：

| 步 | 式子 | 读作 | 你已写过 |
|---|---|---|---|
| 1 | `S = QKᵀ` | S equals Q K transpose | 第 8、9 题 |
| 2 | `S = S / √dₖ` | S equals S over square root of d sub k | 除法（标量） |
| 3 | `A = softmax(S)`，**按行** | A equals softmax of S | 第 10 题 |
| 4 | `O = A·V` | O equals A times V | 第 8 题 |
| 5 | 批量：外面套一层 batch 循环 | — | — |

**写**：`double[][] attention(double[][] Q, double[][] K, double[][] V)`

**对答案**：`dₖ = 2`，`Q = K = [[1,0],[0,1]]`，`V = [[10,0],[0,10]]`

```
     S / √dₖ = [[0.7071, 0     ],
                [0     , 0.7071]]

     A       = [[0.6698, 0.3302],
                [0.3302, 0.6698]]

     O       = [[6.698, 3.302],
                [3.302, 6.698]]
```

（`√2 = 1.414214`）

**写完之后，用一句话回答**：

> **为什么 softmax 要按行，不按列？**

**答案**：第 i 行代表"第 i 个 token 在看向所有 token"。按行归一化表示"它的注意力总共 100%，分给谁多少"。
按列就变成"所有 token 对你的关注度加起来 100%"，没有语义。

**你能说出这句话，说明你真的懂了 attention**，比背十遍公式管用。

## 补充思考题（不用写代码，想一下）

**Q：为什么第 2 步要除以 `√dₖ`？**

**读作**：why divide by square root of d sub k?

设 Q、K 每一维独立、均值 0、方差 1，维度是 dₖ。先看点积：

```
                          dₖ
     q · k   =            Σ    qᵢ kᵢ
                         i=1
```

1. 这是 dₖ 个独立项之和
2. 每一项 `qᵢ kᵢ` 均值 0，方差 `E[qᵢ²] · E[kᵢ²] = 1`
3. dₖ 个独立项相加，**方差相加** → 方差 = dₖ，标准差 = `√dₖ`

不除的话，`dₖ=64` 时点积标准差是 8，logit 散到 ±24，进 softmax 后一个位置接近 1、其余接近 0，**梯度消失，模型学不动**。
除以 `√dₖ` 把方差拉回 1。

> 用到的东西：期望、方差可加、独立变量乘积的期望。**就这三样，高中水平。**
> 整篇 Attention 论文里所有公式的难度都不超过这个量级。

## 遇到不懂的符号怎么办

**先查字典**：[LLM数学符号字典.md](LLM数学符号字典.md)。90% 的符号那里都有。

**字典里没有的，问 AI。** 但**问法决定效果**：

### ❌ 效果差的问法

> "微积分是什么？"
> "讲讲梯度下降。"
> "解释一下 softmax。"

你会得到百科式的、正确但用不上的回答。看完还是不会写代码。

### ✅ 效果好的问法（三个模板）

**模板 1：符号翻译**
> "论文里的 `∂L/∂Wᵢⱼ` 具体在对什么东西求导？用 Java 双重循环怎么写？给我一个 2×2 的具体数字例子。"

**模板 2：验证理解**
> "我觉得 `aᵀb` 是一个数，`abᵀ` 是一个矩阵，对吗？如果对，给我三个例子让我手算，然后给答案。"

**模板 3：从代码反推**
> "这是我自己写的 softmax，输入 `[2,1,0.5]` 输出 `[0.63,0.23,0.14]`。这算对吗？如果对，为什么温度参数调大会变平？"

### 三条使用纪律

1. **一定要带"具体数字例子"这个要求。** 有数字才能验证，没数字只能相信。
2. **一定要跑代码验证 AI 说的话。** AI 会心算错（比如我就把 `KL(q‖p)` 算错过：说成 1.2039，实际 0.3681）。**数值验证是你的护城河**，也是工程师相对理论派的最大优势。
3. **问完之后，自己复述一遍再问 AI"我说得对不对"。** 复述能暴露你到底懂没懂，读一遍不能。

### 最值得问的那类问题

不是"这个概念是什么"，而是：

- "这个符号在这个式子里**具体**在干什么？"
- "如果把它去掉会怎样？"
- "用一个 `double[]` 的例子说说。"

**符号脱离上下文就没有意义。** 同样是 `σ`，在 `σ(x)` 里是 sigmoid，在 `σ²` 里是方差。所以要连上下文一起问。
