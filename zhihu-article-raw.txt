Abstract
We study the offline traveling salesman problem on a line with release times, where requests become available at prescribed times and are served when a unit-speed server visits their locations after their release times. This problem also captures the scheduling of an elevator serving requests on a one-dimensional floor space. The best-known exact approach for the open variant uses quadratic-time dynamic programming, based on explicitly considering pairs of opposite endpoints of the already visited interval.
We present an exact algorithm with an O(m log ⁡m) time complexity and O(m) space complexity, where m is the number of distinct request locations. The key observation is that only requests that become blocking points during monotone traversal can affect the essential state transitions. These blocking points form two directional record sequences according to their release-time offsets. We further show that the seemingly quadratic combinations of left and right progress can be reduced to a linear number of canonical states through dominance and synchronization properties of one-dimensional motion. In particular, states corresponding to sufficiently unbalanced progress can be merged after a single sweep toward the opposite side, while waiting states at the same blocking point can be represented by their most advanced counterpart.
Using these structural properties, the algorithm skips non-critical traversal segments and processes only O(m) effective states, with O(log⁡ m) work per state. This yields an exact O(m log⁡ m)-time algorithm, improving the previously known quadratic-time exact dynamic programming approach.Keywords:

为了方便读者理解，我们可以举个实际的例子：
记当前时刻为0，现在有一条笔直的路（为了方便我们认为它从左到右），一辆大巴车停在start的位置，有m个人要坐车，但是他们有些人还在家里没出发，每个人的位置也不一定都相同。每个人预定的出发时刻是定好的，第i个人到 arrivaliarrival_i （方便公式使用，后续记作 AiA_i ）的时间，就会在路边 posipos_i （方便公式使用，后续记作 PiP_i ）的位置开始等，这时候大巴车只要经过这个位置人就上车。大巴车每一个单位时间刚好也走一个单位距离。大巴车可以沿着路来回开，掉头、停车上人的时间都忽略不计。那么大巴车最早什么时候可以把所有人都接上？
注意这里优化的点不看之前每个人等了多久，只看接到最后一个人的时间。这是这个问题的一个关键。
一般的旅行商问题是NP-hard的，基本上只能穷举所有的顺序才能找到最优解。朴素的一维问题，也就是一开始所有人都在路边等的问题，自然是只要先开到一头、再开到另一头就能全接上。但每个人到达时间不同，这就让问题难度处于两者之间。

from heapq import *
from math import inf
from bisect import bisect

class Solution:
    def elevatorRequests(self, n: int, start: int, requests: list[list[int]]) -> int:
        requests_mapping = {}
        for a, f in requests:
            requests_mapping[f] = max(requests_mapping.get(f, 0), a)
        requests_sorted = sorted(requests_mapping.items())
        N = len(requests_sorted)
        if N == 1:
            return max(requests_sorted[0][1], abs(requests_sorted[0][0] - start))
        # Find "Stuck" points
        left_seq = [requests_sorted[0]]
        for i in range(1, N):
            if requests_sorted[i][1] - requests_sorted[i][0] > left_seq[-1][1] - left_seq[-1][0]:
                left_seq.append(requests_sorted[i])
        # use bisect to find stuck point
        left_seq_bis = [r[1] - r[0] for r in left_seq]
        right_seq = [requests_sorted[-1]]
        for i in range(N - 2, -1, -1):
            if requests_sorted[i][1] + requests_sorted[i][0] > right_seq[-1][1] + right_seq[-1][0]:
                right_seq.append(requests_sorted[i])
        right_seq_bis = [r[1] + r[0] for r in right_seq]

        # min j s.t. right_seq[j][1] > left_seq[i][0]
        # this is the "minimal return point"
        left_opposite = [0] * len(left_seq)
        j = 0
        for i, (_, arrival) in enumerate(left_seq):
            while j < len(right_seq) and right_seq[j][1] <= arrival:
                j += 1
            left_opposite[i] = j
        right_opposite = [0] * len(right_seq)
        j = 0
        for i, (_, arrival) in enumerate(right_seq):
            while j < len(left_seq) and left_seq[j][1] <= arrival:
                j += 1
            right_opposite[i] = j
        ans = inf
        dist = {}
        stuck_left = [-1] * len(left_seq)
        stuck_right = [-1] * len(right_seq)
        # (time, type, params...)
        # type 0: normal state (x, y, is_left)
        # type 1: stuck state (x, 0, is_left)
        queue = [(max(left_seq[0][1], abs(left_seq[0][0] - start)), 0, 0, 0, True),
                 (max(right_seq[0][1], abs(right_seq[0][0] - start)), 0, 0, 0, False)]
        for c, _, x, y, is_left in queue:
            dist[(x, y, is_left)] = c
        for i, (_, arrival) in enumerate(left_seq):
            queue.append((arrival, 1, i, 0, True))
        for i, (_, arrival) in enumerate(right_seq):
            queue.append((arrival, 1, i, 0, False))        
        heapify(queue)
        _lazy_pop = False
        def nonempty():
            return len(queue) - _lazy_pop > 0
        def lazy_pop():
            nonlocal _lazy_pop
            if _lazy_pop:
                heappop(queue)
            else:
                _lazy_pop = True
            return queue[0]

        def enqueue(c, x, y, is_left):
            nonlocal _lazy_pop
            if (x, y, is_left) not in dist or dist[(x, y, is_left)] > c:
                dist[(x, y, is_left)] = c
                if _lazy_pop:
                    heapreplace(queue, (c, 0, x, y, is_left))
                    _lazy_pop = False
                else:
                    heappush(queue, (c, 0, x, y, is_left))
        while nonempty():
            c, type_, x, y, is_left = lazy_pop()
            if c >= ans:
                break
            if type_ == 0:
                if dist[(x, y, is_left)] < c:
                    continue
                # Move to stuck point                
                if is_left:
                    x2 = bisect(left_seq_bis, c - left_seq[x][0], x)
                    if x2 == len(left_seq_bis):
                        # Not stuck
                        ans = min(ans, c + right_seq[y][0] - left_seq[x][0])
                        continue
                    c += left_seq[x2 - 1][0] - left_seq[x][0]
                    x = x2 - 1
                else:
                    x2 = bisect(right_seq_bis, c + right_seq[x][0], x)
                    if x2 == len(right_seq_bis):
                        # Not stuck
                        ans = min(ans, c + right_seq[x][0] - left_seq[y][0])
                        continue
                    c += right_seq[x][0] - right_seq[x2 - 1][0]
                    x = x2 - 1
            else:
                if is_left:
                    y = stuck_left[x]
                else:
                    y = stuck_right[x]
                if y < 0:
                    continue
                if is_left:
                    if x == len(left_seq) - 1:
                        # Not stuck
                        ans = min(ans, c + right_seq[y][0] - left_seq[x][0])
                        continue
                else:
                    if x == len(right_seq) - 1:
                        ans = min(ans, c + right_seq[x][0] - left_seq[y][0])
                        continue
            if is_left:
                stuck_left[x + 1] = max(stuck_left[x + 1], y)
            else:
                stuck_right[x + 1] = max(stuck_right[x + 1], y)
            oppo = left_opposite[x] if is_left else right_opposite[x]
            if y <= oppo - 1:
                # return to oppo - 1 will not stuck
                if is_left:
                    new_dist = right_seq[y][0] * 2 - left_seq[x][0] - right_seq[oppo - 1][0]
                else:
                    new_dist = right_seq[x][0] + left_seq[oppo - 1][0] - left_seq[y][0] * 2
                enqueue(c + new_dist, oppo - 1, x + 1, not is_left)
            else:
                # will it stuck?
                if is_left:
                    new_dist = right_seq[y][0] - left_seq[x][0]
                    if c + new_dist <= right_seq[y][1]:
                        # stuck at y
                        stuck_right[y] = max(stuck_right[y], x + 1)
                    else:
                        enqueue(c + new_dist, y, x + 1, not is_left)
                else:
                    new_dist = right_seq[x][0] - left_seq[y][0]
                    if c + new_dist <= left_seq[y][1]:
                        stuck_left[y] = max(stuck_left[y], x + 1)
                    else:
                        enqueue(c + new_dist, y, x + 1, not is_left)
        return ans

这是会员题版本的数据，数据规模要大一点O(n^2) 动态规划算法
这个问题的多项式解法来源于之前列出的论文，要点是前面说的一点：我们不用关心每个人等待多久，只看最后一个人什么时候完成就行。那么首先，我们可以把同一个位置的人只留下最后到的一个，因为另一个人跟着这个最晚到的人一起上车，解答不会变坏。
其次，如果当前车在路上某一点，车位置的左边A有一个人还没有接到（可能在路边等着了也可能还没出门），车位置的右边B也有一个人还没有接到，而A和B中间有一些人已经上车了。我们现在考虑让A和B之间的人别上车继续在路边等，那么最后答案会变坏吗？答案是不会，因为A和B位置的人还没上车，那么车迟早会开到A，再从A开到B，或者反过来，至少一次。那么A和B之间的已经到达的人在之后反正还是会顺道上车的。这就带来这个问题最重要的一个优化：任何时候，当前状态其实只取决于最左侧没上车的人和最右侧没上车的人，这两个人中间的人可以一律视为没上车，因为车反正还会开过至少一次。
那么问题的状态就可以表示成一个二元组 (x, y) ，x表示当前车接到了第几个人，y表示离当前车最远的还没有被接到的人的位置；如果所有人都上车了，规定y=x。它们都用排好序之后的下标表示，因为没必要考虑车在其他位置的情况，车在不同人之间没必要停车或者掉头。
接下来的状态转移：既然x已经完成，y还没有完成，那么有两种选择，要么向y的方向开到下一个人的位置然后等他上车，也就是转移到 (x + 1, y) （如果y在x左边的话也可能是 (x-1,y) ）；要么跳过下一个人（因为他可能还没到），去先完成y，也就是转移到 (y, x + 1) 或 (y, x - 1) 。哪一种都可能会需要到了之后等人来。记录每个状态的最早到达时间，那么这就是个标准的动态规划算法，因为状态数量为 O(n^2) 所以复杂度也是 O(n^2) 

ChatGPT又贡献了几张插图，凑合看吧这个算法已经很巧妙了，不过其实还可以进一步挖掘这个问题的性质，我们接下来一步一步将它优化到 O(n \log n) 
去掉对问题没有贡献的节点
现在先不考虑最优解的问题，让大巴车在0时刻就位于最左边的人的位置，然后等人上车；随后一路向右开，某些位置上等车到的时候，人已经来了，可以直接上车；另一些位置上车到的时候，人还没来，车需要等人来才能继续。按照这个顺序把所有人都装上车。这时候，我们记录所有等过车的人的位置，称为左侧卡点。这其中固定包括第一个人的位置（即便它在0时间的时候就已经等着了）。
用数学来描述的话，按位置 P_i 排好序之后，从左到右 P_i 依次递增，我们考虑每一个人的 A_i-P_i ，也就是到达时间减去位置，如果它严格大于左边的所有的人对应的值，那么大巴开到这里的时候是必须等这个人的，因为
A_i - P_i > A_j - P_j \Leftrightarrow A_i > A_j + (P_i - P_j) 
也就是说如果大巴在第j个人的位置等了人来，那么再第i个人的位置仍然需要等；反之则说明，如果第j个人已经接上了，开到第i个人的位置上必然人已经来了。
同理，让大巴车在0时刻位于最右边，然后向左开，就可以找到右侧卡点，它对应的值是 A_i + P_i ，处理方式类似。
左侧卡点和右侧卡点各自的最后一个点可能是同一个点，也可能是不同的；如果不同，则一定左侧的最后一个点在右侧的最后一个点的左侧，两边不会交叉。
现在我们说明：所有不在左侧卡点也不在右侧卡点里的点可以全都删掉，不影响结果。
这是因为按照前面动态规划的方式，路上的人永远是从两边往中间接的，当接到这个人的时候，要么它左边所有的人都已经被接上了，要么它右边所有的人都已经被接上了，而如果一个人左边所有人都上车了还需要等他，那么他一定是左侧卡点；反过来如果右边所有人都上车了还需要等他， 就说明他是左侧卡点。如果两侧都不是，那么无论哪边先完成的，走到他这里的时候人一定已经来了，顺便就能上车，那么这个点不考虑也是一样的。
这样问题就可以简化成处理一个单峰状的问题，两边到中间越来越高。这本身并不能降低复杂度，因为最坏情况下一个点都不会去掉，最开始数据就是单峰的；但这可以让问题标准化，方便后续处理。
卡住，还是卡不住？
我们前面讲平方复杂度算法时，说(x, y)可以转移到(x + 1, y)或者(y, x + 1)。但这里其实有个小问题，如果走到x+1的时候，这个位置的人已经来了，可以上车，那么还有必要尝试(y, x + 1)吗？(y, x + 1)首先就必须路过x+1这个位置，这时候故意不让人上车没有意义，所以实际上只需要转移到(x + 1, y)这一个状态就够了。
以此推类，还可以进一步尝试(x+2, y)，直到走到的时候这个位置的人还没来，我们称之为“卡住”，意味着大巴车需要在这里等人。
我们实际上没有必要一步一步判断可以走到哪才会卡住，按照我们前面的左侧卡点和右侧卡点的计算方式，如果某个点会卡住，那么往中间走遇到的后续所有的点都会卡住，所以可以通过一个二分查找直接找到第一个会卡住的位置，这个过程的复杂度是 O(\log n) 
真正的决策只发生在下一个位置会“卡住”的情况下。会产生两条分裂的路线：去下一个位置，然后等待；或者直接去对端，完成对端最远的那个尚未完成的任务，接那个最远的那个没上车的人。
如果一路走到这一侧最后一个卡点然后也完成了，之后会怎么样？之后就不会有任何卡点了，最优的做法是直接去完成对端最远的任务，而且能够保证走到的时候不需要任何等待，所有的任务都顺道完成了。这种情况下我们就直接结算这个状态（当前时间 + 最远未完成到当前位置距离 = 总耗时），根据它更新当前的最佳答案。
这同时表明：我们只需要实际考虑当前位置在一侧、而未完成区间的另一个端点在另一侧的状态，例如当前位置在某个左侧卡点，而未完成区间的最远点在右侧卡点，或者反过来。因为只要两侧卡点中任意一侧的最后一个节点被完成，状态就会被结算，所以不可能出现两侧卡点中最后一个都被完成的情况。
因此接下来我们做以下约定来方便说明：
我们仍然用 (x, y) 来表示一个状态，但是我们永远假定x是个左侧卡点、而y是个右侧卡点，因为反过来的情况是对称的。实际实现的时候，两个方向都需要实现。转移到对端的时候，我们仍然会记为 (y, x + 1) ，省略指示当前在左侧还是右侧的bit位，这时候就变成当前位置在右侧了，按照上下文区分即可，因为我们不考虑从右侧状态出发的情况，所以应该不会混淆。
和之前用过的下标不同，我们接下来重新规定x和y对应的下标：
x代表左侧卡点从左到右排序后的下标
y代表右侧卡点从右到左排序后的下标
注意y的下标和之前是反过来的，y增加表示向左走，这样左侧出发的起始状态永远是 (0, 0) ， y + 1 是y左边的下一个右侧卡点。
卡住然后等待的状态转移
设我们当前状态为 (x, y) ，然后下一步我们选择走到 (x + 1, y) ，而这一步“卡住”了，也就是说我们需要等 x+1 位置的人到达。那么考虑不同的y对应的卡住状态，这些卡住的状态无论从哪里出发、从什么时候开始等待，它结束等待的时间是固定的：都是 x+1 的到达时间。那么既然等完再出发的时间是一致的，而y可能不同，那么其中最优的就是y最大的一个（也就是右侧完成状况最好的一个）。之前的算法都是记录某个状态的最小到达时间，这里我们反其道而行之，以 S(x) 记录能转移到 (x, y) 并且“卡住”在x的状态中，y的最大值是多少；那么在我们刚才说的从 (x, y) 转移到 (x+1, y) 的过程中，由于我们规定了这一步会卡住，所以只需要更新 S(x+1) 的值就够了。这样卡在同一个节点上的状态只需要保留一个。
去对端的状态转移
这是这个算法最核心的关键点。无论前面做了哪些优化，如果仍然将 (x, y) 转移到 (y, x + 1) ，那么可能的状态数仍然减不下来。解决问题的核心在于，如果这里y很小，那么由于x已经完成了，转移到y之后，y是不会卡住的，那么按照前面的讨论，大巴车会立即从y往回开，一直开到某个可能卡住的点为止，才会需要做下一个决策。
从哪里开始有可能会卡住呢？
我们计算一个称为“对侧卡点”的结构。对于左侧卡点x，我们寻找一个最小的右侧卡点y，使得：
A_y > A_x 
我们将它记作 x' ，也就是：
A_{x'} > A_x \\ A_{x' - 1} \le A_x
注意这里 x' 是右侧卡点。同样右侧卡点也有类似的左侧对侧卡点，也记作 y' ，不过文本中不需要用到它。相应地， x+1 的对侧卡点我们就记作 (x+1)' ，依此类推。如果不存在这样的 x' ，记 x' 为右侧最大的下标+1。
现在回答刚才的问题。由于 A_{x'-1} \le A_x ，所以如果已经完成了x，那么 y \le x' - 1 对应的y都是卡不住的，我们直接让大巴车开到y之后掉头开到 x' - 1 ，这些不同的y就都统一转移到了 (x' - 1, x) 。由于转移到的是同一个状态，这些状态只会保留到达时间最早的一个。注意这里转移到 (x' - 1, x) ，不代表接下来走到 x' 一定会卡住；它实际上可能会走得更远，但是我们这次转移只跳到这里，这样才能够保证大量的y会正确合并，从而缩减状态数。
如果 x' 不存在，按照前面的定义，这里 x' - 1 仍然是适用的，可以不区分处理，同时由于这代表之后没有卡点了，也可以直接结算更新备选最优解。
接下来，对于 x' \le y \le (x+1)' 范围的y，我们就直接让它和以前一样转移到 (y, x+1) ，这一步可能卡住也可能卡不住，我们比较一下对应y的到达时间，如果卡住就直接更新 S(y) ，否则正常转移到一个新状态。
那么如果 y > (x+1)' 呢？
这是不可能的！因为这意味着 (x+1)' 在之前就已经完成了，而 (x+1)' 的到达时间比 x+1 更晚！而我们前面说过，我们只在走到 x+1 会卡住的时候才考虑绕道去对端，这和 (x+1)' 已经完成是矛盾的！
所以对于一个走下一步会卡住的状态来说，对于所有可能的y的取值，它下一步转移的状态数不超过
(x+1)' - (x' - 1) + 1 = (x+1)' - x' + 2 
这是对于当前位置为 x 的所有可能的状态转移后的状态数。那么如果对于所有的x求和，这里就会发现它是裂项相消的！那么对于从左侧转移到右侧对端的状态而言，所有可能的状态数不超过 O(n) ，其中 n 是左右卡点的总数。从右侧转移到左侧也同理。
状态O(n)达成！
我们合计一下可能的状态，所有卡住的状态只更新y不更新时间，也不会重复，恰好是n个；去对端转移的是 O(n) ；再加上最初的状态有两个（从左开始和从右开始），那么总状态数就是 O(n) 。
这些状态是原始的平方算法的一个子集。但是我们只能一边计算才能一边找到这些状态，但是我们可以使用优先队列实现的Dijkstra算法，从初始状态开始，每次计算出转移的状态，然后将它放入优先队列，然后每次处理当前时间最小的状态。由于状态转移时时间是单调递增的，所以这样一定不会漏掉状态转移。
算法流程上，我们每次从优先队列中取出一个状态：
如果它是特殊状态 S(x) ，首先判断对应的值是不是有效的：我们初始时将 S(x) 设置为-1，然后直接按对应的时间放进优先队列里，如果出来的时候仍然是-1，说明不可能卡在这个节点上。否则直接将状态替换成 (x, S(x)) 然后继续处理就行了
这个状态从x走到x+1不一定会卡住。我们一直走到下一步会卡住为止，这不需要一步一步走，可以通过一次二分查找快速找到最小的卡点，这一步状态变成 (x_2, y) ——但这个状态不需要进优先队列，我们也不记作总状态数，它只是 (x, y) 出发的中间状态。如果没有下一个卡点，那就直接结算最优解，跳过剩下的步骤。
更新 S(x_2 + 1) ，这样转移到 (x_2, y) 的过程就完成了
如果 y \le x_2' - 1 ，那么尝试走到y然后立即折返走到 x_2' - 1 ，将状态 (x_2' - 1, x_2+1) 入优先队列。否转移到 (y, x_2+1) ，根据是否卡住选择更新 S(y) 还是入优先队列。优先队列中，相同的状态只会保留到达时间最早的，其他的自动忽略。
每一步的最坏情况的时间复杂度：出队 O(\log n) ，二分查找 O(\log n) ，入队 O(\log n) ，总时间复杂度 O(\log n) 。出队最多 O(n) 次，所以总时间复杂度—— O(n \log n) 完成！
具体的优先队列实现会影响复杂度吗？
前面的参考代码使用Lazy Heap作为优先队列，同一个状态可能会多次入堆，出堆的时候才忽略。堆的大小会退化吗？
从流程中不难发现，每次出一次堆，实际上最多尝试入一次堆，所以堆中元素数量是单调不增的。这就说明两件事：
优先队列中元素最多就是 n+2 ：两个起始状态，n个左右卡点的 S(x) 
优先队列的操作是严格 O(\log n) 的
实际处理的状态数为 O(n) ，证明实际入队（含同一状态重复入队）的数量也是 O(n) ，那么实际出队（含同一状态重复出队然后忽略）的数量也是 O(n) ，总复杂度不受影响。
从图论角度说，一般的Dijkstra如果使用Lazy Heap，复杂度通常会从 O(V + E\log V) 退化到 O(V + E \log E) ，但这里每个节点最多只有两条边，而且其中一条边根本不会重新入队（只更新 S(x) ），所以边数和顶点数是同一量级，就不会影响复杂度了。
后记
