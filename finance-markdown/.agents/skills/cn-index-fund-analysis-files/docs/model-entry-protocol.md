# 图片识别交易录入协议

## 唯一入口

本项目不再提供人工填写 CSV 模板或自然语言直接拼接批次的用户入口。交易录入必须以交易图片为事实来源，由模型/视觉能力识别图片后，再交给 `scripts/image_import.py` 预检或原子导入。

交易图片示例：`imports/samples/交易记录样例.jpeg`。

正式交易唯一来源仍然是 `data/transactions.csv`；图片、识别 JSON 和中间 CSV 都不是正式账本。

## 图片识别要求

1. 一张图片中的多笔交易放在同一个识别 JSON 的 `transactions` 数组中。
2. 每条记录尽量输出精确日期、基金代码、交易类型、金额、份额、净值、手续费、状态和备注。
3. 图片中没有显示的字段必须留空，不得用默认值补齐；`0` 只有在图片明确显示为零时使用。
4. 日期必须转换为绝对的 `YYYY-MM-DD`；图片只显示“今天/昨天”且无法确定时，必须暂停并询问。
5. 基金和 ETF 代码必须保存为六位字符串；无法唯一识别时留空并报告，不根据名称猜测。
6. 每条记录可带 `confidence`（0 到 1）和 `uncertain_fields`，置信度低于 0.85 或存在不确定字段时只允许预检，不应直接提交。

## 识别 JSON 最小格式

```json
{
  "image": "交易记录样例.jpeg",
  "transactions": [
    {
      "申请日期": "2026-08-18",
      "基金代码": "021934",
      "交易类型": "买入",
      "申请成交金额": "500",
      "确认状态": "待确认",
      "confidence": 0.96,
      "uncertain_fields": []
    }
  ]
}
```

允许使用常见别名，例如“日期/交易日期”“代码”“金额”“份额”“净值”；脚本会统一映射到 Schema 字段。

## 标准流程

1. 读取 `data/schema.json`、`data/funds.yaml` 和 `data/transactions.csv`。
2. 根据交易图片生成识别 JSON；先检查图片内容和字段置信度。
3. 运行图片入口预检，不加 `--commit`：

```powershell
python .agents/skills/cn-index-fund-analysis-files/scripts/image_import.py \
  imports/samples/交易记录样例.jpeg \
  --recognition-json imports/pending/识别结果.json
```

4. 检查新增、更新、作废、缺失字段、疑似重复和低置信度警告。
5. 只有用户明确要求录入/写入/更新/确认/作废且预检通过时，才加 `--commit` 原子提交。
6. 提交后运行 `validate_data.py` 和 `generate_reports.py`，报告仍待确认的字段和交易ID。

成功提交的中间批次保存到 `imports/archive/`；未提交的识别批次留在 `imports/pending/`，不参与持仓计算。

## 更新、重复与安全边界

- 更新优先通过交易ID定位；没有交易ID时，只有唯一匹配才允许更新。
- 同一申请日期、基金代码、交易类型、金额和份额组合命中已有记录时，默认停止并报告疑似重复。
- 待确认交易不改变确认持仓；已作废交易保留历史行且不参与计算。
- 不直接删除正式账本中的历史行，不手工写入持仓、成本、盈亏和现金流。
- 识别不清或字段矛盾时宁可留空/询问，不得猜测。
- 导入失败时正式账本必须保持不变。
