# 数据结构

## 基金档案

`data/funds.yaml` 是基金元数据的唯一来源。基金代码和 ETF 代码必须使用引号保存为六位字符串。

每只基金包含代码、名称、主题、跟踪指数、关联 ETF、成立日期、销售服务费、赎回说明、天天基金页面和同步日期。关联 ETF 无法唯一确认时必须留空，禁止猜测；此时只允许分析基金净值趋势，不得判断成交额或 OBV。

## 正式交易账本

`data/transactions.csv` 使用 UTF-8 编码和固定表头，是交易事实的唯一来源。

|字段|规则|
|---|---|
|交易ID|唯一且稳定，格式为 TX-YYYYMMDD-基金代码-序号|
|申请日期|必填，YYYY-MM-DD|
|确认日期|待确认时可空|
|基金代码|必填，六位字符串|
|交易类型|买入、定投、卖出、转换转入、转换转出、现金分红|
|申请成交金额|买入/定投必填；卖出建议填写|
|确认份额|已确认的申购、赎回和转换必须填写|
|确认净值|强烈建议确认后填写|
|手续费|未知时留空；0 表示确认无手续费|
|实际到账分红|卖出到账或现金分红；未知时留空|
|确认状态|待确认、已确认、已作废|
|策略标签|首次建仓、回撤加仓、止盈、再平衡等|
|备注|自由文字|
|关联交易ID|转换组或其他关联关系|

录入来源、批次和时间由内部原子导入程序维护。

## 图片识别中间物

- `imports/samples/`：交易图片示例。
- `imports/pending/`：图片识别 JSON 和尚未提交的中间批次；不参与计算。
- `imports/archive/`：成功提交后保存的中间批次；不作为交易事实来源。

用户不直接填写 CSV。所有新增、更新和作废都必须由图片识别入口生成中间批次，再经过重复检查和原子写入。

## 报告

`reports/` 统一保存持仓报告、流水检查和技术面报告。报告全部由脚本生成，不手工维护；不再区分 `generated/` 和 `analysis/`。
