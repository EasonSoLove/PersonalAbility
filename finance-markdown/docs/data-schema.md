# 数据结构

## 基金档案

`data/funds.yaml` 是基金元数据的唯一来源。基金代码和ETF代码必须使用引号保存为六位字符串。

每只基金包含代码、名称、主题、跟踪指数、关联ETF、成立日期、销售服务费、赎回说明、天天基金页面和同步日期。关联ETF无法唯一确认时必须留空，禁止猜测；此时只允许分析基金净值趋势，不得判断放量。

## 正式交易账本

`data/transactions.csv` 使用UTF-8编码和固定表头。

|字段|规则|
|---|---|
|交易ID|唯一且稳定，格式为TX-YYYYMMDD-基金代码-序号|
|申请日期|必填，YYYY-MM-DD|
|确认日期|待确认时可空|
|基金代码|必填，六位字符串|
|交易类型|买入、定投、卖出、转换转入、转换转出、现金分红|
|申请成交金额|买入/定投必填；卖出建议填写|
|确认份额|已确认的申购、赎回和转换必须填写|
|确认净值|强烈建议确认后填写|
|手续费|未知时留空；0表示确认无手续费|
|实际到账分红|卖出到账或现金分红；未知时留空|
|确认状态|待确认、已确认、已作废|
|策略标签|首次建仓、回撤加仓、止盈、再平衡等|
|备注|自由文字|
|关联交易ID|转换组或其他关联关系|

录入来源、批次和时间由导入程序维护。

## 待导入批次

批次表头比正式账本多一个 `操作` 字段，少去系统审计字段，必须与 `data/schema.json` 完全一致。

- 新增：交易ID可以为空；
- 更新：交易ID必须存在；
- 作废：保留记录，仅把状态设为已作废；
- 批次验证和正式写入是原子的，不会出现只导入一半。
